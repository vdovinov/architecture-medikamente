## Список данных для защиты ##

| Тип данных            | Шифрование (хранение) | Шифрование (передача) | Обфускация                              | Обезличивание               |
|-----------------------|-----------------------|:----------------------|-----------------------------------------|-----------------------------|
| ФИО, телефон, email   | AES-256               | TLS 1.3               | Показывать частично                     | Псевдонимизация             |
| Даты рождения, адреса | AES-256               | TLS 1.3               | Скрывать год рождения                   | Агрегация                   |
| Медицинские диагнозы  | AES-256               | TLS 1.3               |                                         | Обезличивание для аналитики |
| Результаты анализов   | AES-256               | TLS 1.3               |                                         | Агрегация статистики        |
| Платёжные данные      | AES-256               | TLS 1.3               | Номер карты: показать последние 4 цифры |                             |
| Данные о сотрудниках  | AES-256               | TLS 1.3               |                                         |                             |

## Механизм тегирования данных ##
Процесс:

Все данные при попадании в систему проходят через Data Classifier (можно реализовать на основе регулярных выражений или ML-модели).

Присваиваются теги:
- ````PII_GENERAL```` – ФИО, телефон, email.
- ````PII_SPECIAL```` – медицинские данные.
- ````FINANCIAL```` – платёжные данные.
- ````STAFF```` – данные сотрудников.
- ````ONSENT_REQUIRED```` – требуется согласие.

Теги хранятся в Data Catalog и используются политиками доступа (ABAC).

## Инструменты и меры обеспечения конфиденциальности в потоках ##

| Поток                                 | Мера защиты                                                   | Инструмент                                                 |
|---------------------------------------|---------------------------------------------------------------|------------------------------------------------------------|
| Сбор данных (портал, моб. приложение) | TLS 1.3, шифрование на клиенте, минимизация данных            | Nginx                                                      |
| Передача между сервисами              | mTLS, сервис-меш                                              | Istio                                                      |
| Хранение в БД                         | Шифрование на уровне приложения (AES-256), управление ключами | HashiCorp Vault для управления ключами + TDE / pgcrypto    |
| Хранение файлов                       | Шифрование на стороне клиента перед записью в S3              | MinIO с SSE‑KMS                                            |
| Аналитика / ML                        | Обезличенные агрегаты, не содержащие прямых ПДн               | Apache Superset с предварительным обезличиванием через dbt |
| Доступ к данным                       | Определение, кому и какие данные видны (ABAC)                 | Open Policy Agent (OPA) + Envoy                            |
| Мониторинг и алертинг (аудит доступа) | Логи всех обращений к чувствительным данным                   | ClickHouse + Vector (для сбора логов)                      |
| Интеграция с лабораторией             | Контроль доступа к API, ограничение объема данных             | Kong API Gateway                                           |

## Процесс 1: Запись и приём пациента (с защитой) ##
````mermaid
flowchart TD
    subgraph Клиент
        Patient[Пациент]
    end

    subgraph Edge
        Ingress[NGINX Ingress<br/>TLS 1.3]
    end

    subgraph K8s_Cluster
        APIGateway[Kong API Gateway<br/>JWT / OAuth2]
        
        subgraph Services
            direction LR
            Appointment[Сервис записи<br/>Java]
            PatientService[Сервис пациентов<br/>Java]
            MedicalRecord[Сервис мед. карт<br/>Java]
        end

        subgraph Data
            direction TB
            Postgres[(PostgreSQL<br/>pgcrypto + Vault<br/>теги: PII, SPECIAL)]
            MinIO[(MinIO<br/>SSE-KMS<br/>шифрование файлов)]
        end

        OPA[Open Policy Agent<br/>ABAC]
        Audit[Vector -> ClickHouse<br/>логи доступа]
        Vault[HashiCorp Vault<br/>ключи шифрования]
    end

    Patient -->|ФИО, дата рожд., телефон, email, адрес, полис| Ingress
    Ingress -->|TLS| APIGateway
    APIGateway -->|проверка токена| Appointment
    APIGateway -->|проверка токена| PatientService
    
    Appointment -->|создание записи| Postgres
    PatientService -->|регистрация пациента| Postgres
    PatientService -->|сканы документов| MinIO
    
    MedicalRecord -->|чтение/запись карты| MinIO
    MedicalRecord -->|метаданные| Postgres
    
    OPA -.->|политики ABAC| Services
    Vault -.->|ключи| Postgres
    Vault -.->|ключи| MinIO
    Audit -.->|логи всех операций| Services
    Audit -.->|логи| APIGateway
    
    Doctor[Врач] -->|запрос через портал| APIGateway
    APIGateway -->|проверка OPA| MedicalRecord
    MedicalRecord -->|только свои пациенты| Doctor
````

## Процесс 3: Аналитика и отчётность (с защитой) ##
````mermaid
flowchart TD
    subgraph K8s_Cluster
        subgraph DataLake
            Raw[(MinIO Raw<br/>сырые данные)]

        MinIO[(MinIO<br/>мед. файлы)]

    Sources -->|ETL с шифрованием| Raw

    DeID -->|обезличенные данные<br/>без ФИО, диагнозов| Curated
    Curated --> BI
    BI -->|дашборды| Management[Руководство]
    
    Cron -->|удаление по тегу RETENTION| Raw
    Cron -->|удаление по тегу RETENTION| Curated
    
    Audit -.->|логи доступа к BI| BI
    Audit -.->|логи ETL| DeID
````
